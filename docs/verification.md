Интеграционные тесты включают конкурентную постановку/снятие лайков, конкурентную регистрацию просмотров, окно дедупликации и следующий интервал, отсутствие просмотров от GET/автора/admin/черновика, уникальность и FK PostgreSQL, UTC-границы и нулевые дни, публичную/личную статистику и последствия удаления/снятия публикации, два одновременных редактора одной версии, ротацию/replay/logout и конкурентный refresh.

В ограниченной среде прямой `go test` не может подключаться к TCP PostgreSQL, поэтому тот же интеграционный набор выполнен внутри Go-контейнера. Go proxy загружен через разрешённый curl в временный локальный кеш; production Docker build загрузил зависимости штатно через Go proxy и проверил go.sum. Эти ограничения не требуют изменений приложения.

Порт 5432 уже занят другим окружением, поэтому проверочный Compose использовал POSTGRES_PORT=55433; приложение — порт 8080. Временный Compose-проект `blog-api-verify` остановлен, его БД/volume удалены. Отдельный контейнер интеграционной БД `blog-api-test-db` остался на 55432: среда запрещает прямую команду удаления через Docker socket. Можно удалить вручную: `docker rm -f blog-api-test-db`.

Swagger UI проверен как доступный HTML по `/docs`; интерактивная загрузка CDN в браузере отдельно не проверялась. Нагрузочные испытания и production deployment не выполнялись и не входят в заявленные проверки. Git-репозиторий в исходной папке отсутствует, поэтому Git diff-check неприменим; проверены файлы и форматирование напрямую.
